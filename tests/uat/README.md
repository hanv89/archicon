# Onboarding UAT kit

A small self-service test that measures one thing: **can someone new to this
repository get their first rendered Azure architecture diagram quickly, working
only from the README?**

If you've just tried this project for the first time, running this test and
sharing the result is the single most useful contribution you can make — it
tells us exactly where the README loses people.

## What's here

| File | Purpose |
|---|---|
| `rubric.md` | The fixed scoring rules — the task, the timing method, what counts as a "stuck point", and the pass/fail bar. Read this first. |
| `session-log-template.md` | A blank log to fill in while you run the test. Copy it, fill every `<…>` field. |
| `sample-results/` | Example filled-in logs, so you can see what a completed run looks like. |

## How to run it

1. Read `rubric.md`.
2. Ideally, have someone watch while you work (an *observed* run captures **why**
   you got stuck, not just **that** you did) — but a careful solo run is still
   valuable.
3. Start a stopwatch, open the repo's main README, and do the task: *get your
   first rendered Azure architecture diagram*.
4. Fill in a copy of `session-log-template.md` as you go — timing, every stuck
   point, verbatim quotes if observed.

## How to submit your result

Open a GitHub issue with your filled-in log pasted in:
<https://github.com/hanv89/archicon/issues>

Use a title like `UAT: onboarding run — <your handle>`. A failed run (you got
stuck, it took too long) is **more** useful than a clean pass — it points at a
real gap.

We review submitted runs and fold the friction points back into the README.
This process is intentionally lightweight for now; if submissions pick up, we'll
formalise it.
